# RACT Public Quality Leaderboard

This page tracks RACT's own quality metrics over time. The goal is to make the loop's progress visible and comparable across commits.

## v0.4.0 ALM leaderboard columns

`evals/LEADERBOARD.md` (regenerated by `evals/leaderboard/update.py`) carries three columns beyond the per-corpus cells that the substrate `v0.4.0` tag shipped. All three are defined by ADR-0025.

- `claimed_pass_rate` — the pass rate the provider itself reports, averaged across the Aider Polyglot subset and the SWE-bench Lite subset. Denominator is the subset size (`passed + failed + skipped`).
- `attested_pass_rate` — the fraction of runs whose rootknot sidecars verify under all three signatures (RK-1 generator, RK-3 environment, AL-1 anti-lazy) with `reversal_taint == "clean"` and every gate PASS or handshake-resolved. Runs with no rootknot file (e.g., the run crashed before rootknot generation) are EXCLUDED from both numerator and denominator. This is a deliberate scoping choice — a crash is a different failure kind than a reward-hacking attempt that cleared some gates but not others.
- `attestation_gap` — `claimed - attested`, clamped to zero-or-positive. Interpretation from Lateral Chain branch C of ALM module_07: a gap above 0.20 is a provider signal (reward-hacking rate); 0.05 to 0.20 is a mixed signal (partly gate strictness, partly provider); under 0.05 is measurement noise. The thresholds are speculative until a v0.5 empirical calibration lands (Flagged gap in module_07).

The gap is the reward-hacking signal. A model that scores high on claimed pass rate but low on attested pass rate is exactly what the ALM gates exist to surface.

## Methodology

- **Coverage** is measured with `pytest --cov=src` against the full suite.
- **Dead-code auction** is `ract auction list` run against RACT itself; candidates are modules with no inbound references from production code.
- **Novelty detector** scores are from `ract novelty scan` against representative probes.
- **Mutation score** is from `mutmut` targeted at a single file using `tests/test_<file>.py`; a higher percentage means more mutants were killed by the test suite.
