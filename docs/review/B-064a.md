## What this increment does

- `approval_needed(steps, mode)`: true only in `default` mode, for a plan of two or more steps with at
  least one file target (ADR-0049 D12 and the card's point 1).
- `resolve_answer(steps, line)`: `approve` keeps every step; `skip <n>` drops step n and every later step with the
  same file target (its dependents, named in `skipped`); `cancel` keeps nothing and returns `refused`; an answer
  that is not understood asks again. `edit` is not built: it asks again with that sentence (the card's point 2).
  The text is never run.
- `ApprovalMemory`: the plans approved in the session, by `plan_hash` (K's canonical hash). A resumed session is
  given the saved hashes and does not ask for the same plan again; a changed plan has a new hash and asks again
  (the card's point 6).
- `headless_refusal(steps, mode)`: the sentence for `ract -p` in `default` with a plan that needs approval;
  it names `--accept-edits` (the card's point 4). The exit code (3) is not set here.
