# Review: B-033s, the input broker core (not yet wired)

Branch: `work/mason/B-033s`. This commit adds `src/ract/input_broker.py` and its tests. It changes no
existing file, so no senior area is touched yet. The wiring into the REPL (`repl.py`, the prompt and
the turn loop) is a later commit and is senior; it gets its own review file.

## What the core does

- `InputBroker` with modes `prompt`, `approval` and `turn`. A line is an intent in `prompt`, the answer
  to the open question in `approval` (and only then), and a queued item in `turn`.
- The queue is the prepared `QueueModel` (package J, `src/ract/ui/queue_view.py`), so `/queue` renders
  `queue.model` with `list_lines` and `cancel` uses `QueueModel.drop`; one queue, one list of ids.
- `queue.items()`, `queue.cancel(position)`; `input.queued` and `input.withdrawn` are emitted through the
  `emit` callback with the fields docs/EVENTS_SESSION.md names (`text`, `position`).

## Proposed `input.withdrawn` fields

The schema already names `position` (integer). The proposal is no new field: the operator took the item
back for editing, and the text is not needed on the event (it was already shown by `input.queued`).

## What the core cannot do

- It does not read the terminal, so it cannot make Ctrl-C return the prompt; that is the wiring's job and
  is measured with real pseudo-terminal runs in package 6.
- It cannot widen a tier, read outside the path jail, skip a gate, or emit an unsigned event.
- A queued line is never routed as an approval answer: `turn` mode queues whatever the text is.

Delete `src/ract/input_broker.py` and `tests/test_input_broker.py` (no other file refers to them yet).

## Decision: polled console reader, not a blocking read (package 6)

A blocking console read cannot be stopped at turn end, so a read left over from the turn would take
the operator's next prompt line. `ConsoleLineSource` polls instead: it reads a key only when one is
waiting (`msvcrt.kbhit` and `getwch` on Windows, injected in tests), assembles a line on Enter,
handles Backspace, and treats Ctrl-C as a stop with no line. The default is taken and recorded
here; the operator may choose otherwise. Not yet wired into the REPL, and the pseudo-terminal checks
are still to run.

## Wiring (package 6, behind a flag)

`ReplSession._start_type_ahead` starts a `TypeAhead` thread for the duration of a turn, only when
`RACT_TYPE_AHEAD=1`, on Windows, with a console on stdin. The turn's wait stops it on every exit. The
flag is off by default, so the existing behaviour is unchanged. Queued lines: `QueuedInput.take_first` removes the next line, and the prompt loop runs it before reading
the console (`ReplSession._take_queued`). Still a gap before READY-SENIOR: the queued line is sent as a
new turn at the prompt, not at the next model-request boundary of the running turn; the pseudo-terminal runs (Ctrl-C under 2 s, type-ahead, EOF and double Ctrl-C per mode) are
not run. The TypeAhead test and its implementation were committed together, so no separate red run exists
for that test.
