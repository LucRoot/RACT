# Review: H4, a step is not reported done before its file is applied

Branch: `work/H1-H4`. Senior areas touched: `src/ract/executor/steps.py` and
`src/ract/executor/substrate_adapter.py`. Nothing lands without the BUILDER.

## Hunks in senior areas

1. `steps.py`, `Executor` attribute `hold_step_report`: the flag the substrate sets. One-sentence
   reason: the executor must know a step's files are applied later, so it can hold the report.
2. `steps.py`, `_step_done`: when the flag is set, the finished step is held in `_held_step` and
   no `step.finished` is emitted. One-sentence reason: the "done" event printed before the apply.
3. `steps.py`, new `release_held_step(outcome, error)`: emits the held step with its real outcome
   and runs the checkpoint only for `done`. One-sentence reason: the single place a held step is
   reported.
4. `substrate_adapter.py`, `run_via_substrate` is now a wrapper that sets the flag, calls the old
   body (renamed `_run_via_substrate_steps`), and in `finally` releases any held step as `done`
   (result ok) or `refused` / `failed` (anything else). One-sentence reason: every exit from a
   run must end the held step with the outcome the disk shows.
5. `substrate_adapter.py`, two `release_held_step("done")` calls: after a successful apply, and
   in the answer-step branch (no file is written there). One-sentence reason: the success path
   releases the step it held.

## Failing-first output

`tests/test_read_only_step_report.py` ran before the change and failed:
`assert "[step 1] done" not in text`, with the text output containing `[step 1] done` for a
read-only `src/calc.py`. After the change it passes (1 passed). The harness case "read-only file"
now prints `[step 1] refused (0.7s)` and the same error sentence the turn summary gives.

## What the change cannot do

- It cannot widen a tier, read outside the path jail, skip a gate, or emit an unsigned event.
  The events it emits are the same `step.finished` events with an outcome that the existing
  schema already allows (`done`, `failed`, `refused`).
- It cannot report `done` for a step whose apply was refused: `done` is released only after
  `apply_commit_to_working_tree` returns without skipped paths.
- Known limit: a step that raises inside the executor, before `_step_done`, is still reported by
  the existing exception path, not by this release. The `finally` covers returns, not raises
  that escape `run_via_substrate`; the BUILDER should decide whether that needs a release too.

`substrate_adapter.py` (the H4 commits). The read-only test and the hint for H1 are separate
commits and can stay.
